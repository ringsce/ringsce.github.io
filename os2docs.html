OS/2 Warp ARM64

Complete documentation for building, deploying, and developing OS/2 Warp 4.52 on AArch64 hardware.

Introduction

OS/2 Warp 4.52 ARM64 Edition is a bare-metal operating system for AArch64 processors. This is not a Linux distribution, Android runtime, or emulation layer—it's a complete reimplementation of the classic OS/2 architecture for modern ARM64 hardware.

⚡ What is OS/2 Warp?

OS/2 (Operating System/2) was IBM's enterprise operating system developed in the late 1980s and 1990s. Known for its stability, multitasking capabilities, and elegant Workplace Shell interface, OS/2 powered everything from ATMs to corporate servers. This ARM64 port brings OS/2's proven architecture to modern hardware.

Key Features

⚡

Bare Metal

Direct hardware access with zero virtualization overhead. Pure ARM64 execution with UEFI boot.

🗂️

Multi-Filesystem VFS

EXT4, FAT32, FAT16, and exFAT drivers with full read/write support. GPT partition management.

⌨️

43 Keyboard Layouts

Global keyboard support across 9 script families including Latin, Cyrillic, Arabic, CJK, and more.

⚙️

CONFIG.SYS Services

Classic OS/2 service management—no systemd complexity. Simple, deterministic boot sequence.

Quick Start

Get OS/2 Warp running in QEMU in under 5 minutes.

Prerequisites

  • Linux host with qemu-system-aarch64 installed
  • ARM64 cross-compiler: aarch64-elf-gcc or clang with LLD
  • CMake 3.20+ and Ninja build system
  • AAVMF UEFI firmware for QEMU

1. Clone the Repository

$ git clone https://github.com/os2warp-arm64/os2warp.git
$ cd os2warp

2. Build the System

$ cmake -B build \
    -DCMAKE_TOOLCHAIN_FILE=toolchain/aarch64-elf.cmake \
    -DTOOLCHAIN_USE_CLANG=ON \
    -G Ninja

$ cmake --build build -j$(nproc)

3. Create Disk Image

$ ./scripts/mkdisk.sh build/os2warp452.img

# Creates 6 GiB GPT image with 4 partitions:
# P1: EFI (FAT32, 100 MiB)    → /boot/efi
# P2: OS2ROOT (EXT4, 4 GiB)   → /
# P3: FAT16DATA (512 MiB)     → /mnt/fat16
# P4: EXFATUSB (1 GiB)        → /mnt/exfat

4. Run in QEMU

$ ./scripts/run_qemu.sh build/os2warp452.img

# Launches QEMU with:
# • Machine: virt,gic-version=3
# • CPU: cortex-a72 (4 cores)
# • Memory: 2 GiB
# • UEFI: AAVMF_CODE.fd
✅ Expected Output

You should see the OS/2 boot sequence, service initialization, and finally the C:\> prompt.

Installation

Bare Metal Installation

To install OS/2 Warp on real ARM64 hardware:

  1. Prepare the target device (Raspberry Pi 4/5, ARM server, etc.)
  2. Create a bootable SD card or USB drive with the disk image
  3. Configure UEFI firmware to boot from the device
  4. Boot and enjoy classic OS/2 on modern hardware
# Example: Write to SD card (replace /dev/sdX)
$ sudo dd if=build/os2warp452.img of=/dev/sdX bs=4M status=progress
$ sudo sync
⚠️ Warning

The dd command will erase all data on the target device. Double-check the device path before running this command!

Building from Source

Toolchain Setup

OS/2 Warp ARM64 requires a freestanding AArch64 cross-compiler. You have two options:

Option 1: GCC (aarch64-elf-gcc)

# On Ubuntu/Debian:
$ sudo apt install gcc-aarch64-linux-gnu binutils-aarch64-linux-gnu

# Or build from source:
$ wget https://ftp.gnu.org/gnu/gcc/gcc-13.2.0/gcc-13.2.0.tar.gz
$ tar xzf gcc-13.2.0.tar.gz
$ cd gcc-13.2.0
$ ./configure --target=aarch64-elf --enable-languages=c --without-headers
$ make -j$(nproc)
$ sudo make install

Option 2: Clang + LLD (Recommended)

# On Ubuntu/Debian:
$ sudo apt install clang lld llvm

# Test it works:
$ clang --version
$ ld.lld --version

Build Configuration

# GCC toolchain:
$ cmake -B build \
    -DCMAKE_TOOLCHAIN_FILE=toolchain/aarch64-elf.cmake \
    -G Ninja

# Clang/LLVM toolchain (recommended):
$ cmake -B build \
    -DCMAKE_TOOLCHAIN_FILE=toolchain/aarch64-elf.cmake \
    -DTOOLCHAIN_USE_CLANG=ON \
    -G Ninja

# Build everything:
$ cmake --build build -j$(nproc)

Boot Flow

  1. UEFI firmware loads BOOTAA64.EFI from EFI partition
  2. Bootloader initializes GOP graphics, reads memory map
  3. Bootloader loads kernel8.img to 0x80000
  4. Kernel initializes UART, memory, terminal
  5. Boot orchestrator calls os2_boot_init()
  6. Service manager starts CRITICAL services (VFS, TERMINAL, SHELL)
  7. Service manager starts AUTO services (BLKDEV, KEYBOARD, SYSLOG)
  8. Filesystem automount mounts all 4 partitions
  9. Shell displays C:\> prompt

CONFIG.SYS Reference

CONFIG.SYS is OS/2's main system configuration file. It controls device drivers, services, environment variables, and boot options.

Service Directives

SERVICE=<name>,<mode>    REM Description

; Modes:
;   CRITICAL  = Start at boot, panic if fails
;   AUTO      = Start at boot
;   MANUAL    = Start on demand
;   DISABLED  = Do not start

SERVICE=VFS,CRITICAL         REM Virtual filesystem (panic if fails)
SERVICE=KEYBOARD,AUTO        REM Keyboard driver (auto-start)
SERVICE=NETBIOS,MANUAL       REM Network BIOS (on demand)
SERVICE=LEGACY,DISABLED      REM Old driver (skip)

Device Drivers

DEVICE=<path> [/options]
BASEDEV=<name> [/options]    ; For critical boot drivers

DEVICE=C:\OS2\UART.SYS
DEVICE=C:\OS2\KBD.SYS /LAYOUT:en_US
DEVICE=C:\OS2\TERMINAL.SYS /MODE:1920x1080 /DEPTH:32
BASEDEV=NVME.ADD /V /A:0
BASEDEV=VIRTIO_BLK.ADD

Filesystem Installable File Systems (IFS)

IFS=<path> [/options]

IFS=C:\OS2\EXT4.IFS /CACHE:8192 /LAZY:ON
IFS=C:\OS2\FAT32.IFS /CACHE:4096
IFS=C:\OS2\EXFAT.IFS /CACHE:2048

Environment Variables

SET <variable>=<value>

SET COMSPEC=C:\OS2\CMD.EXE
SET PATH=C:\OS2;C:\OS2\SYSTEM;C:\;
SET LIBPATH=.;C:\OS2\DLL;C:\OS2\SYSTEM;
SET PROCESSES=256
SET THREADS=1024
SET ARCH=AARCH64
SET CPU_CORES=4

Filesystem Drivers

OS/2 Warp ARM64 includes a complete VFS (Virtual Filesystem) layer with four production-ready filesystem drivers.

Supported Filesystems

Filesystem Max File Size Max Volume Features
EXT4 16 TiB 1 EiB Primary OS filesystem, extents, journaling
FAT32 4 GiB 2 TiB Cross-platform compatibility, LFN support
FAT16 2 GiB 2 GiB Legacy compatibility, simple structure
exFAT 128 PiB 128 PiB Modern FAT, no 4 GiB limit, UTF-16 names

Partition Layout

GPT Partition Table (6 GiB disk image)

┌──────────────────────────────────────────────────────┐
│ P1: EFI System Partition (FAT32, 100 MiB)           │
│     Mount: /boot/efi                                  │
│     Contains: BOOTAA64.EFI, kernel8.img              │
├──────────────────────────────────────────────────────┤
│ P2: OS2ROOT (EXT4, 4 GiB)                           │
│     Mount: /                                          │
│     Contains: OS/2 system files, /bin, /os2, /etc    │
├──────────────────────────────────────────────────────┤
│ P3: FAT16DATA (FAT16, 512 MiB)                      │
│     Mount: /mnt/fat16                                 │
│     Use: Data exchange, DOS compatibility            │
├──────────────────────────────────────────────────────┤
│ P4: EXFATUSB (exFAT, 1 GiB)                         │
│     Mount: /mnt/exfat                                 │
│     Use: USB drives, SD cards, large files           │
└──────────────────────────────────────────────────────┘

EXT4 Driver Features

  • Extent-based allocation: Modern extent tree with depth-first traversal
  • Block-map inodes: Legacy indirect block support for older filesystems
  • 64-bit addressing: Support for volumes > 2 TiB
  • Per-group bitmaps: Efficient block and inode allocation
  • Directory operations: Linear scan, entry insertion, deletion
  • Sparse files: Returns zeros for unmapped blocks
  • Large files: i_size_hi for files > 4 GiB

VFS API Example

// Initialize VFS and register drivers
vfs_init();
vfs_register_driver(ext4_get_driver());
vfs_register_driver(fat32_get_driver());

// Auto-mount a partition
blkdev_t *disk = blkdev_get("nvme0");
vfs_automount(disk, lba_start, "/", false);

// Open, read, write files
int fd = vfs_open("/os2/system/config.sys", VFS_O_RDONLY);
vfs_read(fd, buf, sizeof(buf));
vfs_close(fd);

// Directory operations
vfs_dir_t *dir = vfs_opendir("/os2/dll");
vfs_dirent_t *ent;
while ((ent = vfs_readdir(dir)) != NULL) {
    term_printf("%s\n", ent->name);
}
vfs_closedir(dir);

Features

  • USB HID abstraction: Hardware-independent scancode layer
  • Dead key composition: ´ + a → á, ^ + e → ê, etc.
  • AltGr layer support: Access to € £ @ symbols
  • Modifier tracking: Shift, Ctrl, Alt, AltGr, Meta, CapsLock, NumLock
  • RTL scripts: Right-to-left rendering for Arabic and Hebrew
  • Multi-codepoint keys: Support for CJK input methods

Debugging

UART Serial Output

OS/2 Warp outputs debug messages via UART serial. Connect with:

$ screen /dev/ttyUSB0 115200
# or
$ minicom -D /dev/ttyUSB0 -b 115200

QEMU Debugging

Launch QEMU with GDB server:

$ qemu-system-aarch64 \
    -machine virt,gic-version=3 \
    -cpu cortex-a72 \
    -m 2G \
    -bios AAVMF_CODE.fd \
    -drive if=none,id=hd0,file=os2warp452.img,format=raw \
    -device virtio-blk-pci,drive=hd0 \
    -serial stdio \
    -s -S

# In another terminal:
$ aarch64-elf-gdb build/kernel/kernel_elf
(gdb) target remote :1234
(gdb) break kernel_main
(gdb) continue

Common Issues

Issue Cause Solution
QEMU doesn't boot Missing UEFI firmware Install qemu-efi-aarch64 or edk2-aarch64
Black screen after boot GOP framebuffer issue Check QEMU -device ramfb or VGA
Filesystem not mounting Partition table corrupt Re-run mkdisk.sh to rebuild image
Service fails to start Dependency missing Check CONFIG.SYS service order

Contributing

OS/2 Warp ARM64 is an open-source community project. Contributions are welcome!

Development Workflow

  1. Fork the repository on GitHub
  2. Create a feature branch: git checkout -b feature/my-driver
  3. Make your changes and test thoroughly
  4. Follow the coding style (K&R C with 4-space indents)
  5. Commit with clear messages: git commit -m "Add SATA driver"
  6. Push to your fork: git push origin feature/my-driver
  7. Open a pull request on GitHub

Coding Standards

  • Language: C11 with freestanding extensions
  • Style: K&R with 4-space indentation, no tabs
  • Naming: snake_case for functions/variables, UPPER_CASE for macros
  • Comments: C-style /* */, // for single-line
  • Headers: Include guards with #pragma once
